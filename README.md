# ⭐ Starr — Lightning Wallet

A non-custodial Bitcoin Lightning wallet for iOS and Android.

## Features

- ⚡ **Lightning payments** — send and receive over Lightning
- 🔗 **On-chain and Spark** — receive to a Bitcoin address or a Spark address, send to both
- 🔤 **LNURL-Pay** — pay Lightning addresses and LNURL-Pay links
- 🕓 **History** — payment list with filters, pagination and a detail screen
- 🗺 **Merchant map** — nearby places that accept Bitcoin, from [BTC Map](https://btcmap.org)
- 🔐 **Non-custodial** — the 24-word phrase stays in platform secure storage
- 📱 **iPhone and iPad** — responsive layouts, light and dark theme

## Architecture

Starr uses the **Breez SDK Spark**
(`@breeztech/breez-sdk-spark-react-native`) for all wallet operations. The SDK
runs in the app, so there is no node to host and no server component.

```
app/**                                  expo-router screens
  → src/stores/walletStore.ts           zustand: shared wallet state
  → src/services/breez/BreezService.ts  the only file that imports the SDK
    → @breeztech/breez-sdk-spark-react-native
```

`BreezService` translates the SDK tagged unions into the plain domain types in
`src/types/wallet.ts`. Screens use only those types. Amounts are `bigint`
satoshis everywhere.

## Tech Stack

- **React Native** 0.86 with **Expo** SDK 57
- **Breez SDK Spark** for Lightning, on-chain and Spark payments
- **Zustand** for state, **Expo Router** for navigation
- **TypeScript**

## Getting Started

### Prerequisites

- Node.js 20+
- Xcode (iOS) or Android Studio (Android)
- An EAS account for cloud builds

### A native build is necessary

The Breez SDK is a native module. **Expo Go cannot run this app** — you must
install a development client build first.

```bash
npm install
npm run ios          # expo run:ios: builds the native project, then runs it
npm run android      # expo run:android
npm start            # Metro, for a device that already has the dev client
```

Or build the dev client in the cloud:

```bash
eas build --profile development --platform ios
```

`ios/` and `android/` are generated by `expo prebuild` and are gitignored.
Change `app.json` instead of the native projects. Any change to `app.json`
plugins or to a native dependency needs a new build, not a Metro reload.

## Configuration

Create a `.env` file in the root directory:

```bash
# Required. Without an API key BreezService.initialize throws.
EXPO_PUBLIC_BREEZ_API_KEY=your_breez_api_key
EXPO_PUBLIC_BREEZ_NETWORK=mainnet          # mainnet | regtest

# Optional
EXPO_PUBLIC_BREEZ_WORKING_DIR=/absolute/path
EXPO_PUBLIC_BREEZ_SYNC_INTERVAL_SECS=60

# Android map tiles. Read at build time by app.config.js, not at runtime.
GOOGLE_MAPS_API_KEY=your_google_maps_api_key
```

All wallet variables are read in one place, `src/config/breez.ts`.

`GOOGLE_MAPS_API_KEY` goes into `AndroidManifest.xml` as
`com.google.android.geo.API_KEY`. The key needs the **Maps SDK for Android**
API, active billing, and — if it has Android application restrictions — the
package name `com.starrwallet` together with the SHA-1 of the signing
certificate. A key that fails these checks gives a black map, not an error.

`.env` is gitignored and is not uploaded to EAS. For cloud builds, set the same
variables as EAS environment variables (`eas env:list --environment production`).

## Building for Production

```bash
eas build --platform android --profile preview      # APK, internal distribution
eas build --platform android --profile production   # AAB for the store
eas build --platform ios --profile production
```

A push to `main` starts the production build for both platforms through
[.eas/workflows/create-production-builds.yml](.eas/workflows/create-production-builds.yml).
To start the same workflow by hand:

```bash
eas workflow:run .eas/workflows/create-production-builds.yml --ref main
```

## Security

### Key management

The 24-word phrase (256 bits of entropy) is the only secret. It is stored with
`expo-secure-store` and `requireAuthentication: true`, so every read shows the
native biometric or passcode prompt. iOS uses Keychain Services, Android uses
the Keystore.

`AuthGate` wraps the app: it shows a privacy overlay when the app becomes
inactive and re-authenticates on a real background-to-active transition.

### Backup

The phrase is the backup. There is no cloud backup and no channel state to
back up — Spark restores the wallet from the phrase alone.

- **Never** share the recovery phrase
- Keep the 24 words offline, in a safe place
- The phrase is shown once, during onboarding
